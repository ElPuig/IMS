# Fixes:

## Head of Studies/Deputy Head of Studies could not edit a colleague's schedule without triggering a false "overlaps with itself" error:
- Root cause: the schedule-sync pipeline (`ems.attendance_template`'s `_reconcile_teacher_groups`/`_plan_schedule_sync`, `ems.attendance_schedule`'s `find_room_conflicts`, and the working-schedules import wizard's own conflict-detection helpers) ran its own internal "does a matching template/schedule line already exist?" searches under the acting user's own security context. A Head of Studies/Deputy Head of Studies/Director (in `group_teacher` + `group_head_of_studies`, neither of which grants `ems.attendance_template`/`ems.attendance_schedule`'s "all data" record rule reserved for `group_academic_admin`) editing a colleague's schedule couldn't see that colleague's own already-existing template under their own record-rule visibility, so the sync believed nothing existed yet and created a duplicate — which then collided with the very record it couldn't see, raising a confusing "This session overlaps with another one" error on a save that should have been a no-op.
- Fix: those internal bookkeeping searches now run with `sudo()`, since whether a duplicate/overlap already exists is a fact about the whole school's schedule, never something that should depend on the acting user's own visibility.
- Also fixed: Head of Studies/Deputy Head of Studies/Director now have full ("all data") access to `ems.attendance_template`/`ems.attendance_schedule`, matching the access level they already had on `ems.teaching` — the attendance-template list's "Show only mine" filter now defaults to checked so this doesn't flood their list view with every teacher's schedule by default.
- Fixed a Catalan typo ("meuss" → "meus") in the shared "Show only mine" filter label, used across several search views.
